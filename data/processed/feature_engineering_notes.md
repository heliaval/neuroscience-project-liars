# Feature Engineering Notes (Section 10)

Generated by `src/features.py`. Written for someone who has never opened
this module and needs to know exactly what was computed, how, and why --
peer of `data/processed/eeg_preprocessing_notes.md`.

## Grain and schema

**Single-brain table** (`single_brain.parquet`): one row per
`(session_id, dyad_trial_seq, participant_id)` -- one row per participant
per trial, matching `trial_table.csv`'s long form. Experiment 1 classifies
participant-trials; Experiment 6 (observer-only) filters `role ==
'observer'`; Experiment 3 splits chronologically within participant --
all row filters on this grain.

`DecisionMaking` and `Feedback` features are distinct columns
(`..._dm_...` / `..._fb_...`) on the same row rather than doubling row
count with a stimulus key, since the experiments treat a trial's two
stimulus epochs as two views of one observation, not two observations.

Partner features are NOT materialized as columns. Experiment 7's "both
participants' EEG" is served by a self-join on
`(session_id, dyad_trial_seq)` swapping `participant_id`.

**Dyadic table** (`dyadic.parquet`): one row per
`(session_id, dyad_trial_seq)` -- a second table, not extra columns hung
off one arbitrary participant's row. A dyadic feature belongs to the
trial, not to either participant; hanging it off one participant's row
would make Experiment 6's `role == 'observer'` filter silently carry or
drop dyadic information depending on an arbitrary convention.

**Direction convention, applied everywhere: deceiver -> observer.** Signal
A is the deceiver, signal B the observer. `deceiver_id`/`observer_id` are
explicit columns on every dyadic row.

**Feature dictionary** (`feature_dictionary.csv`, 3,960 rows, one per
feature column): `feature_name, table, feature_group, channel, band,
stimulus, window, statistic, metric, reliability, reliability_reason,
n_samples_in_window, window_duration_ms, n_cycles`.

## Exclusion set divergence between DecisionMaking and Feedback (verified, not assumed)

The plan's Step 1.3 asked whether the two stimuli's exclusion sets are
identical. They are NOT, at the fine grain. `alignment_not_recoverable`
(the whole `sub22_sub19` session) hits both stimuli identically -- 968
participant-trials, zero symmetric difference. But `rejected_in_archive`
diverges: DecisionMaking excludes round 8/trial 2 in `sub21_sub20` while
Feedback excludes round 8/trial 1 in the same session (and similarly two
trials in `sub23_sub24`) -- 6 participant-trials excluded in DM only, 6
different ones in FB only, 12 total, zero overlap. This is a real
per-archive divergence (each stimulus's own artifact rejection ran
independently) -- confirmed by set comparison on `epoch_index.csv`, not
inferred. Consequence: per-stimulus nullity
(`dm_excluded_reason`/`fb_excluded_reason` columns) is required, not
optional. None of these 12 rows are dropped entirely -- each has exactly
one stimulus's columns null, the other stimulus intact.

## Spectral method: bandpass on the full epoch, then window -- not naive Welch/FFT binning

At fs=100 Hz the windows are 200-1010 ms. A periodogram computed directly
on a short window has Rayleigh resolution 1/T: ~4.8 Hz for the 200 ms
Feedback-pre window, ~1.0 Hz for the 1010 ms DecisionMaking-post window.
Binning that into delta (0.5-4 Hz) would put delta below the first
non-DC bin and return a number shaped like a feature that is not one.

Instead, for each session/stimulus/role: the FULL epoch (350 samples
DecisionMaking, 120 samples Feedback, read straight from
`data/raw/Preprocessed/<stimulus>/<session>.mat`, the same archive files
`src/preprocessing.py` reads -- via direct import of its `SessionMat` and
`compute_alignment` rather than reimplementing alignment) is bandpass
filtered with a zero-phase IIR
(`scipy.signal.butter(4, [lo, hi], btype='band', output='sos')` +
`scipy.signal.sosfiltfilt`). SOS form was used because a 0.5 Hz corner at
fs=100 Hz is numerically fragile in transfer-function (`b, a`) form.
Filtering the full epoch and THEN slicing the window avoids the
edge-transient contamination that filtering a 21-sample window directly
would produce. The Hilbert analytic signal
(`scipy.signal.hilbert`, axis=samples) of the filtered full epoch is then
sliced per window; band power = mean(|analytic|^2) over the window's
samples, per trial x channel -- non-negative by construction (min
observed 6.6e-07, max 113,712, no negatives, no Inf). The same analytic
signals are reused for the dyadic PLV/coherency measures (computed once
per session, used twice).

Filter stability was verified empirically before any feature was
computed: `sosfreqz` on all 5 bands at order 4 showed finite impulse
responses and mean passband gain 0.959-0.964 for every band -- printed at
run time, order 4 was kept for all bands (no need to lower it).

`scipy.signal.welch` appears exactly once in this module, as the gamma
diagnostic below -- never as a feature.

## Reliability tiering

`n_cycles = window_duration_seconds x band_low_edge_Hz`.
`n_cycles >= 3` -> reliable; `1 <= n_cycles < 3` -> marginal;
`n_cycles < 1` -> unreliable. Published for every frequency and dyadic
feature in `feature_dictionary.csv`.

Measured window durations: DecisionMaking pre/onset = 0.50 s, post =
1.00 s; Feedback pre = 0.20 s, onset = 0.30 s, post = 0.69 s.

**Delta is unreliable in every one of the 6 windows in this dataset** --
even its best case (DecisionMaking-post, 1.0 s window) reaches only 0.5
cycles, half of the 1-cycle floor. Theta is marginal almost everywhere,
reliable only in DecisionMaking-post. Alpha/beta are reliable in most
windows, marginal only in the two shortest Feedback windows. Gamma is
reliable everywhere (its high low-edge clears 3 cycles even in the
200 ms Feedback-pre window). `dy_corr_broad_*` (Pearson correlation) has
no cycle-count constraint and is tagged reliable throughout.

**Unreliable-tier features were computed and tagged, not dropped.** Any
downstream use of an `unreliable`-tier feature (this means every
`pow_delta_*`, `dy_plv_delta_*`, `dy_coh_delta_*` column, all 6 windows)
must carry that label. Deleting them silently and computing them silently
would have both been wrong; tagging is the honest option and is what this
module does.

## Gamma decision

Before emitting gamma features, mean Welch PSD (1-50 Hz, full 350-sample
DecisionMaking epoch, 3 sessions x 30 channels x 484 trials,
`nperseg=256`) was inspected (printed at run time):

| band range | mean power |
|---|---|
| 0.5-4 Hz | 3.6059 |
| 4-8 Hz | 1.2189 |
| 8-13 Hz | 1.2523 |
| 13-30 Hz | 0.3438 |
| 30-45 Hz | 0.2561 |
| 45-50 Hz | 0.0139 |

Power in 30-45 Hz (0.2561) is the same order of magnitude as 13-30 Hz
beta (0.3438) -- roughly three-quarters of it -- and roughly 18x larger
than power at 45-50 Hz (0.0139), where the archive's antialiasing
roll-off toward Nyquist (fs/2 = 50 Hz) actually shows up. There is no
sudden drop at 30 Hz consistent with a low-pass filter placed below
gamma; the decline from beta into gamma is the ordinary 1/f-like EEG
spectral shape, not a noise floor. **Decision: gamma is kept**, banded
30-45 Hz. The upper edge is set at 45 Hz rather than 50 (Nyquist) because
the last few Hz below Nyquist show real roll-off (44 Hz: 0.117, 46 Hz:
0.028, 48 Hz: 0.002 in the finer-grained diagnostic run during design),
and 45 Hz stays clear of it.

## Baseline correction

Whether the archive was baseline-corrected before shipping is unknown
(documented as unknown in `eeg_preprocessing_notes.md`). **No new
baseline correction is applied here** -- doing so would compound an
unknown prior state with an assumption. The `pre` window's own
`td_mean_*` feature gives a model explicit access to baseline-level
amplitude instead of having it silently removed.

## Time-domain features

Computed on the UNFILTERED windowed signal, per channel x stimulus x
window: `mean`, `std`, `ptp` (max-min), `peakamp` (signed amplitude at
the sample of max |amplitude|), `peaklat` (that sample's latency in ms,
relative to stimulus onset t=0), `slope` (least-squares line fit,
microvolt/s). All six kept -- none judged redundant even at the 21-sample
Feedback-pre window. 6 stats x 30 channels x 6 stimulus-windows = 1,080
columns.

## Behavioral features

Joined from `trial_table.csv` on `(session_id, dyad_trial_seq,
participant_id)`, never recomputed:
`reaction_time_sec, trials_so_far, prior_deception_count,
prior_deception_rate, prior_outcome, prior_condition, round,
pinfo_bart_score`. Join verified 1:1 (row count preserved). Tagged
`feature_group = behavioral`. `prior_outcome`/`prior_condition` are null
on each dyad's first trial by construction (24 nulls = 12 dyads x 2
participants) -- a real absence, not recomputed or imputed.

## Dyadic / inter-brain features

Computed on the 30 HOMOLOGOUS channel pairs only (same electrode name in
both brains -- verified same clab order within a session for both
player and observer structs, confirmed across 4 sample sessions):

- `corr`: Pearson correlation of A/B's RAW (unfiltered) window samples,
  broadband (`band='broad'`). Range [-1, 1]. Observed range in this run:
  [-0.9605, 0.9802].
- `plv`: `abs(mean(exp(i*(phase_A - phase_B))))` over window samples, per
  band. Range [0, 1]. Observed: [0.00022, 0.99999].
- `coh`: amplitude-weighted coherency magnitude,
  `abs(sum(A*conj(B))) / sqrt(sum(|A|^2)*sum(|B|^2))`, per band.
  Range [0, 1]. Observed: [0.00021, 0.99997].

`scipy.signal.coherence` (Welch coherence) was deliberately NOT used --
magnitude-squared coherence on a single un-averaged segment is
identically 1.0 by construction; Welch coherence needs multiple
segments/tapers to average over, and a 21-101 sample window supplies
none. The analytic-signal coherency magnitude above is the correct
single-trial substitute; it is named `coh` here to mean exactly that --
NOT classical Welch coherence, and this distinction should travel with
the name whenever it is used downstream.

**Mandatory caveat: inter-brain synchrony here is a statistical
relationship between two simultaneously recorded signals; it is NOT
evidence of communication between brains.** (Also stated in the module
docstring of `src/features.py`, per section 26's requirement that it
travel with every presentation of these results.)

**Small-sample bias**: single-trial PLV and coherency are upward-biased
at small sample counts -- a 21-sample window will show high `plv`/`coh`
for genuinely unrelated signals. The bias is roughly constant given equal
window length, so it does not by itself manufacture a truth-vs-deception
difference, but absolute `plv`/`coh` values must never be read as
"synchrony strength."

**Skipped, with reason**: `xcorrmax`/`xcorrlag` and mutual information
were marked optional/lower-priority in the plan and are skipped here in
favor of shipping the required set (corr/plv/coh) fully validated --
both would need meaningful additional validation work this task's budget
did not extend to (a 21-sample window makes a lag estimate close to
meaningless; MI needs a binning scheme that itself needs tuning).
Wavelet coherence is skipped outright, per the plan: it needs several
cycles per scale within the window, and these windows do not supply them
for any band where it would add anything over the Hilbert measures above.

## Inter-brain network tensor (section 26)

`interbrain_networks.npz`: 30 electrodes grouped into 5 regions by 10-20
topographic proximity (not data-driven):

- frontal: Fp2, F9, F10, F7, F3, Fz, F4, F8
- central: FC5, FC1, FC2, FC6, C3, Cz, C4
- temporal: T7, T8, CP5, CP6
- parietal: CP1, CP2, P7, P3, Pz, P4, P8
- occipital: PO3, PO4, O1, O2

Each region's complex analytic signal is the mean of its member channels'
analytic signals. Deceiver-region x observer-region PLV is stored per
band per window: 5 x 5 x 5 x 3 windows x 2 stimuli, one 4D block
(`region x region x band x window`) per trial, keyed by
`(session_id, round, trial)` and stimulus-prefixed arrays
(`dm_tensor`/`fb_tensor`). 5x5x5x6 = 750 values per trial across both
stimuli, matching the plan's estimate.

## Output format

**Parquet** (via `pyarrow`, added to `requirements.txt` and installed in
this task -- it was not previously installed). Chosen over `.npz` because
it preserves named columns and dtypes (required for interpretability,
sections 25/34) and compresses well. Real measured shapes:
`single_brain.parquet` 21,296 rows x 2,000 columns; `dyadic.parquet`
10,648 rows x 1,991 columns; `feature_dictionary.csv` 3,960 rows. A flat
CSV at this volume (~21k x 2,000 float32 values) would be several hundred
MB of text and slow to reload -- the same reasoning
`src/preprocessing.py` used to choose `.npz` over CSV for the epoch
arrays.

Column-count check against the plan's own arithmetic: 900 `pow_*`
(5 bands x 30 channels x 6 stimulus-windows) + 1,080 `td_*` (6 stats x 30
channels x 6 stimulus-windows) + behavioral/key columns = 2,000 total on
`single_brain.parquet`. Dyadic: 180 `dy_corr_broad_*` (30 channels x 6
stimulus-windows) + 1,800 `dy_plv_*`/`dy_coh_*` (2 metrics x 5 bands x 30
channels x 6 stimulus-windows) + key/reason columns = 1,991 total.
`feature_dictionary.csv`: 900 + 1,080 + 180 + 1,800 = 3,960 rows,
matching exactly.

## Bug found and fixed during validation

An early version of `assemble_single_brain` appended every
participant-trial row unconditionally, regardless of whether either
stimulus had an extracted epoch. This put `sub22_sub19`'s 968
participant-trials into `single_brain.parquet` with all-null EEG columns
instead of dropping them entirely (22,264 rows instead of the correct
21,296) -- caught by Step 9 Check 1 (row-count reconciliation against the
independently-computed expectation), fixed by tracking
`any_stim_available` per row and only appending when at least one
stimulus succeeded, and the full pipeline was re-run before any
downstream artifact used the file. The comment documenting this is left
in `src/features.py` at the fix site.
