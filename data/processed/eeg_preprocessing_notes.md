# EEG Preprocessing Notes (Section 9)

Generated by `src/preprocessing.py`. This document is written for someone who
has never opened `Preprocessed.zip` and needs to know exactly what is in it,
what was done to it here, and what was not.

## Source archive

`Preprocessed.zip`, figshare article 24760827, file id 43502097.
1,453,534,919 bytes, md5 `ca696df2146ba54bd25f28e2ec065c98` (verified against
the figshare API's `size` and `supplied_md5` before extraction). Extracted to
`data/raw/Preprocessed/`. Contains two folders, `DecisionMaking/` and
`Feedback/`, each with 23 `.mat` files named `Player_subXX_Observer_subYY.mat`
-- one per recording session, matching `trial_table.csv`'s 23 `session_id`
values exactly (verified: the set difference in both directions is empty).

## File format

MATLAB v7 (not v7.3/HDF5 -- `scipy.io.loadmat` reads every file directly, no
`h5py` needed). Each file has two top-level (1,1) structs: `player` and
`observer`. Role is identified by the archive's own `filename` field
(`[...]_player.set` / `[...]_observer.set`), never by struct position or
dict-key order.

Each struct has exactly these fields -- this list is exhaustive, there is no
history/comments/provenance field:

| Field | Shape / type | Meaning |
|---|---|---|
| `fs` | (1,1) uint8 | Sampling rate, Hz |
| `x` | (n_samples, n_channels, n_epochs) float64 | The EEG data, already epoched |
| `clab` | (1, n_channels) cell of str | Channel names |
| `y` | (n_classes, n_epochs) uint8 | One-hot class label per epoch |
| `className` | (1, n_classes) cell of str | Class names for `y`'s rows |
| `t` | (1, n_samples) int16 | The epoch's own time axis, ms, t=0 = onset |
| `filename` | str | Archive's own `.set` filename (role identity) |

**The data is already epoched, not continuous.** "Windowing" in this module
means selecting a sub-window inside an existing epoch, never cutting from a
continuous trace.

## Sampling rate, channels, units, epoch extent

- **Sampling rate**: 100 Hz in every one of the 23 x 2 = 46 files checked
  (both `player.fs` and `observer.fs`).
- **Channels**: 30, named (10-20 system: F7, F3, Fz, F4, F8, FC5, FC1, FC2,
  FC6, T7, C3, Cz, C4, T8, CP5, CP1, CP2, CP6, P7, P3, Pz, P4, P8, PO3, PO4,
  O1, O2, F9, F10, Fp2). **Channel order is NOT identical across all
  sessions** -- exactly two distinct orderings exist across the 23 sessions
  (they differ only in whether PO4 or O1 comes first). `src/preprocessing.py`
  carries each session's own channel-name list in its output rather than
  assuming a single global order; downstream code must read
  `channel_names_deceiver` / `channel_names_observer` per session, not
  hardcode a channel list.
- **Units**: not stated anywhere in the archive. Observed value range on
  DecisionMaking epochs: roughly -180 to +150 (5-session sample); Feedback:
  roughly -228 to +362. Both ranges and the near-zero medians are consistent
  with microvolts (typical scalp EEG amplitude is tens of microvolts) and
  inconsistent with volts (~1e-5 scale) or raw ADC counts (typically
  thousands). Recorded as **likely microvolts, not confirmed by the
  archive** -- not rescaled by this module.
- **Epoch extent**:
  - DecisionMaking: t = -500 to +2990 ms, 350 samples. t=0 = decision-making
    onset (per `data/raw/readme.txt`).
  - Feedback: t = -200 to +990 ms, 120 samples. t=0 = feedback onset.

## Prior preprocessing -- documented vs. not documented

**Documented** (in `data/raw/readme.txt`, the only source of any description):
the epochs are "preprocessed, artifact-free EEG epochs, aligned with the
decision-making or feedback onset."

**Not documented anywhere in the archive** (no field in the `.mat` structs
carries this, and no extra readme/text file ships inside `Preprocessed.zip`
itself):
- Filter band (high-pass / low-pass / notch)
- Re-referencing scheme
- Downsampling method (the data arrives at 100 Hz; whether this was the
  native recording rate or a downsampled rate is not stated)
- ICA or other artifact-correction procedure
- The exact artifact-rejection criterion (amplitude threshold, algorithm,
  etc.) used to produce the "artifact-free" epochs
- Baseline-correction window, if any was applied

These are recorded here as unknown, not inferred from the signal and
presented as fact.

## Alignment: how epochs map to `trial_table.csv` rows

No per-epoch index, event-latency, or rejection-mask field exists in the
archive (the field list above is exhaustive), so alignment was recovered
from the epoch's own class label rather than trusting on-disk order blindly.

**Method**: for each (session, stimulus) pair, independently:
1. Build the trial table's per-trial key sequence, sorted by (round, trial)
   -- the same order `src/timeline.py` establishes as chronological.
   - DecisionMaking key: (`card_type_raw`, `condition`) -- 4 distinct values.
   - Feedback key: (`outcome`,) -- 2 distinct values.
2. Build the archive's per-epoch key sequence from `y`/`className`, in
   on-disk epoch order.
3. Run `difflib.SequenceMatcher` between the two sequences; take its
   `ratio()` as a fit score.
4. If `ratio() >= 0.98`: accept. 'equal' blocks give a direct
   table-row-to-epoch-index map. 'delete' blocks (a table trial absent from
   the epochs) are recorded excluded, reason `rejected_in_archive`.
5. If `ratio() < 0.98`: the whole session is unrecoverable for that
   stimulus -- every trial is recorded excluded, reason
   `alignment_not_recoverable`. No positional guess is made.

**Evidence this method is trustworthy**: the archive's `className` codes
'instL'/'instT' were found to use the *opposite* polarity from the trial
table's `card_type_raw` L/T codes -- confirmed as a pure labeling-convention
difference (not a misalignment) because the 'S' (spontaneous) trials, which
carry no such swap ambiguity, matched the table 1:1 at every position in
every session with equal epoch and trial counts.

**Results, per session** (23 sessions, both stimuli independently):
- 20 sessions: epoch count == trial count (484), `ratio()` == 1.0, zero
  exclusions.
- `Player_sub21_Observer_sub20`: 483 epochs vs 484 trials in both stimuli.
  The diff identifies the same missing trial (round 8, trial 2) in both
  DecisionMaking (ratio 0.999) and Feedback (ratio 0.999) independently --
  Feedback's weaker 2-valued key converging on the identical trial as
  DecisionMaking's stronger 4-valued key cross-validates the result.
- `Player_sub23_Observer_sub24`: 482 epochs vs 484 trials in both stimuli.
  The diff identifies the same two missing trials (round 6 trial 2, round
  10 trial 2) in both stimuli independently (ratio 0.998 both).
- `Player_sub22_Observer_sub19`: 484 epochs, matching the trial count
  exactly, **but the class-label sequence does not correspond to the trial
  table's sequence at all** -- ratio 0.353 (DecisionMaking) / 0.300
  (Feedback), versus >=0.998 for every other session. A shift scan over
  constant offsets -10..+10 topped out at 268/484 (55%) match, ruling out a
  simple off-by-N error. No latency, event-timestamp, or reaction-time
  field exists in the struct to attempt a correlation-based recovery. This
  session is **excluded entirely, in both stimuli** -- 484 trials x 2
  participants x 2 stimuli x 3 windows = 5,808 rows in `epoch_index.csv`
  carry `excluded_reason = alignment_not_recoverable`. This is a data
  problem in the archive (or in how this file was matched to a session),
  not a modeling decision, and it is reported rather than worked around.

**t=0 vs. the trial table's `trigger_ts_sec`**: `src/timeline.py` anchors
`trigger_ts_sec` on the `obsInp_*` event (observer's input) for observer
rows and the last `playerinput_*` event before it for deceiver rows. The
archive's epochs are aligned to "decision-making onset," which the archive
does not further define relative to those specific trigger events -- it may
be the same moment as the player's response trigger, or a different one
(e.g. card presentation). **This module does not assume the two are the
same moment.** Every window boundary recorded in `epoch_index.csv`
(`window_start_ms`/`window_end_ms`) is relative to the **epoch's own t=0**
as defined by the archive's `t` field, not to `trigger_ts_sec`. Downstream
code must not treat `window_start_ms` as an offset from `trigger_ts_sec`.

## Windows chosen

Trial spacing (from `trial_table.csv` alone, no EEG needed): median
inter-trial gap 9.37 s, 5th percentile 8.57 s, minimum 7.77 s (within a
session; the up-to-274 s between-round breaks are excluded from this
figure). Every window below is far shorter than the 7.77 s floor, so none
can reach into the previous trial -- **epoch extent, not trial spacing, is
what constrains window choice here.**

**Section 9's illustrative -2000 ms window and Section 18's six 250 ms
sliding windows spanning -1500 to 0 ms are NOT constructible from
`Preprocessed.zip`.** The archive's pre-onset extent is only -500 ms
(DecisionMaking) or -200 ms (Feedback) -- nowhere near -1500 or -2000 ms.
Building either would require re-deriving epochs from continuous data in
`Raw.zip`, which is out of this task's download scope (the user approved
only `Preprocessed.zip`). **This is reported as a finding for the user's
decision, not solved here, and `Raw.zip` was not downloaded.**

| Stimulus | Window | Start (ms) | End (ms) | Samples | Justification |
|---|---|---|---|---|---|
| DecisionMaking | pre | -500 | 0 | 51 | Entire available pre-decision period; closest constructible analog to a pre-decision baseline/anticipation window, capped by the archive at -500ms (not -2000ms). |
| DecisionMaking | onset | -200 | +300 | 51 | Spans the decision onset itself; ERP-style window. |
| DecisionMaking | post | +300 | +1300 | 101 | Post-decision processing, well inside the +2990ms ceiling. |
| Feedback | pre | -200 | 0 | 21 | Entire available pre-feedback baseline. |
| Feedback | onset | 0 | +300 | 31 | Early feedback-locked response (FRN/P300-type window). |
| Feedback | post | +300 | +990 | 70 | Late feedback processing. |

Three windows were kept per stimulus (not collapsed to fewer) because they
are not near-identical relative to their extents (51/51/101 of 350 samples
for DecisionMaking; 21/31/70 of 120 samples for Feedback).

## Output format and location

`.npz` (compressed), one file per session per stimulus, at
`data/processed/epochs/<stimulus>/<session_id>.npz`. Each holds, per window
name, a `<window>_deceiver` and `<window>_observer` float32 array of shape
`(n_extracted_trials, 30, n_window_samples)`, plus `channel_names_deceiver`,
`channel_names_observer`, `sampling_rate_hz`, `trial_round`, `trial_num`, and
per-window `_start_ms`/`_end_ms`/`_n_samples`. On-disk size: ~737 MB for 44
files (22 sessions x 2 stimuli; `Player_sub22_Observer_sub19` produced no
files since it was excluded entirely), against a pre-run estimate of ~868
MB.

Rationale for per-session `.npz` over a single `.h5`: epoch counts are
nearly uniform across sessions (482-484, with one session dropped entirely)
so there is no non-uniformity that would favour `.h5`'s random access; a
flat CSV was never viable at this volume (~850 MB of float data); per-session
files need no extra dependency and let Section 10 stream one session at a
time instead of loading the whole corpus.

`data/processed/epoch_index.csv` is the join table: one row per
(session_id, participant_id, round, trial, stimulus, window_name), 133,584
rows total (22,264 participant-trials x 2 stimuli x 3 windows), including
rows for every excluded trial with a populated `excluded_reason` -- nothing
is silently omitted.

## Why `trial_table.csv` was not modified

`eeg_window_start` / `eeg_window_end` remain null in `trial_table.csv`.
Three reasons:
1. `trial_table.csv` is a deterministic output of `src/timeline.py`; an
   in-place edit here would be destroyed the next time that script runs.
2. There are three windows per trial per stimulus (six total), not one --
   two scalar columns cannot express a multi-window scheme without an
   arbitrary choice of which window "counts."
3. `epoch_index.csv` shares `trial_table.csv`'s grain keys (`pair_id`,
   `session_id`, `round`, `trial`, `participant_id`), so a one-line merge
   recovers everything Section 10 needs. The index is the more expressive
   artifact.

## Validation results (Step 6 of the plan; see PROGRESS.md for full output)

1. Session coverage: 22/23 sessions have extracted epochs; the 23rd
   (`sub22_sub19`) has zero extracted epochs but is fully represented with
   excluded rows -- no session silently missing from the index.
2. Per-session accounting: `n_extracted + n_excluded == n_trials` verified
   for all 23 sessions.
3. Total accounting: `extracted + excluded == 22,264` verified for every
   one of the 6 stimulus/window combinations.
4. Sample counts: uniform within each stimulus/window combination across
   all 21,290 extracted rows (DecisionMaking pre/onset/post: 51/51/101;
   Feedback pre/onset/post: 21/31/70) -- 0 mismatches.
5. Shape and role: channel dimension is 30 everywhere; spot-checked 3
   sessions (`sub01_sub02`, `sub09_sub10`, `sub24_sub23`) and confirmed the
   archive's `player` struct's participant identity (from its `.set`
   filename) matches the trial table's deceiver `participant_id` for that
   session in every case.
6. Numerical integrity: 0 NaN, 0 Inf, 0 flat (zero-variance) channel-epochs,
   0 all-zero channel-epochs, across all 264 extracted arrays checked.
7. Value range: DecisionMaking roughly -180 to +150, Feedback roughly -228
   to +362 (5-session sample) -- consistent with the microvolt-scale range
   observed during Step 3 inspection; no scaling drift between inspection
   and output.
8. Timestamp spot-check: 5 trials across 5 different sessions, arithmetic
   shown -- window sample count == (end_ms - start_ms)/1000 * fs + 1 in
   every case.
9. Determinism: re-running `process_session` on one session twice produced
   byte-identical output arrays.
